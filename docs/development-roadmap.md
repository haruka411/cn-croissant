# cn-croissant 后续开发计划

更新日期：2026-06-30

本文基于 [项目状态与代码审查](./project-status-vs-en-croissant.md) 的结论编写，只列尚未完成、被禁用、有正确性问题或需要重构的任务。已可用的棋盘、走法、记谱、引擎实时分析、对弈、时钟、悔棋、PGN 浏览、IndexedDB 索引、云库候选、对弈开局库查询等不再作为计划项重复列入。

## 发布打包约定

Windows 面向用户的 release zip 包统一命名为：

```text
cn-croissant-win-release.zip
```

zip 文件名不附加版本号，版本信息以应用版本、提交、标签和 release 说明为准。

## 原则

1. 先修正确性与假数据，再加新功能：错误结论/假统计比"功能缺失"更伤可信度。
2. En Croissant 的数据库、训练、报告、账户不能直接照搬，必须按象棋重新设计。
3. 功能开放标准高于"代码存在"：入口开放前必须有完整 UX、真实数据来源、正确性判断和基本测试。
4. 上游国际象棋遗留模块（含不参与编译的 Rust 死代码）在完成象棋替代方案前保持隔离。

## 阶段 0：正确性与误导性入口清理（最高优先级）

目标：消除会误导用户或产生错误结论的问题。这些是审查中确认的 bug，应先于新功能处理。

任务：

- **统一中文记谱生成器**：着法节点的 `san` 改用 `notation.ts` 的 `formatRelativeMove`，废弃 `xiangqi.ts` 中缺消歧的 `moveToText`，修复叠线子记谱歧义。
- **不要暴露未完成的棋规切换**：当前 GUI 只保留统一基础裁决（将死、困毙、120 半回合自然和、三次同局面和、单方长将判负）。若后续实现 AsianRule / ChineseRule / SkyRule / ComputerRule / YitianRule，必须先参考可靠实现并完成整体裁决逻辑，不得再用零散长将/长捉参数冒充规则差异。
- **修 DatabasePanel React key 冲突**：`key={game.path}` → `key={game.id}`，选中判定同步改 `game.id`。
- 为规则核心继续补边界测试：多兵同线消歧、复杂重复局面、起始 FEN 非标准半回合数等。

验收：

- 记谱在叠线子（双车/双马同线）场景下无歧义，导入导出一致。
- 未完成的棋规切换不会出现在设置页或对弈配置中。

## 阶段 1：引擎进程加固

目标：让引擎分析在崩溃、切换、退出场景下稳定，不泄漏进程。

任务：

- `stop_analysis` 区分"暂停"与"卸载"：卸载时 `kill()` 进程并从 map 移除。
- 实现 `kill_engines` 实体，在应用退出钩子统一杀掉全部常驻引擎，避免 Pikafish 孤儿进程。
- 引擎崩溃恢复：reader 线程在 EOF/出错时置 `running=false` 并发送带错误的 finished 事件；保留 stderr 用于诊断；可加 isready 心跳/超时 watchdog。
- 引擎日志加环形缓冲上限，停止每 200ms 全量 clone + IPC 回传。
- 内置 Pikafish 按 CPU 特性（avx2/bmi2/vnni512）选最快二进制，而非固定取第一个兼容版。
- UCCI 的 MultiPV 下发语法与 Threads/Hash 风格对齐。

验收：

- 反复增删/切换引擎不累积常驻进程；应用关闭后无孤儿引擎。
- 引擎中途崩溃时前端显示错误而非永久 loading。

## 阶段 2：棋谱库格式解析与本地统计

目标：让 CBL/OBK/XQF 从占位升级为真实可用，本地棋谱库才能产生价值。

任务：

- **OBK 研究索引**：对弈开局库已在 Rust 后端支持 `.obk/.xqb/.pfBook` 查询；本阶段要做的是把 OBK 作为本地研究资料接入数据库/分析页统计，支持任意局面候选着、胜和负统计和来源文件展示。
- **CBL/CBR**：实现 CCBridge 二进制记录格式解析（区分 `CCBridge` 单库 zlib 与 `CCBridgeLibrary` 容器两种 magic），支持单局逐局浏览、打开、加入局面统计。
- 解除 `MAX_PARSE_CBL_LIBRARIES = 128` 硬截断，或改为按需/分批解析 1104+ 个库。
- **XQF**：按规范实现头部密钥解密（KeyXY 系列异或）+ 着法树遍历，支持变着、注释、对局头；否则真实 .xqf 文件无法导入。
- 支持更多本地格式的统一导入：PGN-like、WXF、中文纵线、txt、XQF。
- 统一象棋棋谱库 schema：棋局、棋手、赛事、着法、局面、来源文件、标签；结果字段不再硬套国象 `1-0`/`1/2-1/2`。

验收：

- CBL/PGN/XQF 真实棋谱能进入统一索引并逐局浏览；OBK/XQB/PFBook 能作为开局候选数据进入分析/研究视图。
- 当前局面能查到历史走法、出现次数和结果统计（数据来自真实棋谱，非假数据）。

## 阶段 3：象棋开局库与布局研究

目标：在已可用于对弈的开局库查询基础上，把开局库作为研究资料接入，不开发布局训练。

任务：

- 在分析页开局区域显示本地 `.obk/.xqb/.pfBook` 候选着，复用后端查询逻辑，避免前后端两套不一致的 key/走法解析。
- 设计开局库/布局库数据结构；支持从当前棋局、当前局面或导入棋谱创建布局树。
- 支持给节点添加推荐着、备选着、文字说明、来源棋局。
- 支持缺口提示：缺少己方准备、缺少对方回应、分支覆盖不足。
- 暂不开发训练模式、间隔重复、"用户走一方对方按库回应"流程。

验收：

- 用户可从当前棋局或导入棋谱生成可浏览的开局树。
- 人机/机机对弈中的开局库走法与分析页开局候选使用同一套查询结果和合法性校验。
- 不依赖原版国际象棋 PGN/chessops repertoire。

## 阶段 4：复盘报告增强

目标：把局势折线图扩展为可复用的复盘报告。

任务：

- 在折线图上标记关键转折点；列出每步实战着、引擎最佳着、分差变化。
- 支持点击报告项跳转到对应棋步。
- 支持为局面添加文字批注和自定义标签。
- 设计象棋语境的评价标签（漏着/缓手/战术机会/布局新招），不用国际象棋 NAG。
- 报告数据随棋谱保存或导出，不需每次重新分析。
- 复盘用的 `analyze_position` 改用常驻进程而非每局面重启引擎，加快报告生成。

验收：

- 报告页能定位问题棋步；报告数据可复用。

## 阶段 5：云库稳定化

目标：让在线候选着查询成为可靠辅助，而不是脆弱外部依赖。

任务：

- 明确云库接口许可、稳定性和离线替代策略。
- 设计缓存过期、错误重试、限流、断网提示；请求去重 / 最小间隔，避免快速切局面并发打 chessdb。
- 统一当前局面、候选着、胜负倾向、残局结论的查询层。
- 云库不可用时本地引擎、棋谱库、对弈继续可用，不阻塞主流程。

验收：

- 当前局面能稳定查询云端候选着；网络失败时用户能看懂原因且本地功能继续可用。

## 阶段 6：残局训练正式版

目标：把已完整但被禁用的 `XiangqiPuzzleTrainer` 整理为可开放功能。

任务：

- 题源质量筛选，剔除无训练意义或异常局面。
- 离线模式：用本地引擎兜底对方应手，不强依赖在线云库（当前禁用的主因）。
- 完善对方自动回应、胜负/必胜/必和/无法判定提示、正误反馈（正确/次优/错误/完成）、复盘信息。
- 占位页文案改中文并 i18n。

验收：

- 主页残局入口重新开放；离线可用；每道题有明确目标、对方回应、结束反馈。

## 阶段 7：界面与象棋专业化

目标：从"可用的迁移版"变成更自然的象棋工具。

任务：

- **渲染坐标轴**（复用 `.coordinate` 类 + svgPoint），或确认产品决定不要。
- **全流程 i18n**：棋盘 aria-label 用中文棋子名、记谱栏标题、报告图表空状态/tooltip、占位页。
- 棋谱栏增加中文/坐标记谱显示切换。
- 局面图导出（FEN/WXF 生成图片）。
- 清理设置页国象残留项（子力显示、开局库最小局数、SRS 难度）与 `IconChess` 图标。
- 继续打磨自定义 SVG/PNG 棋子主题：当前两者均支持目录选择、缺失检查和 70%–200% 缩放；后续重点是移动端预览、异常图片容错和默认目录提示。

验收：

- 主流程中文界面无明显国际象棋术语残留；棋谱阅读、局面分享、主题设置符合象棋用户习惯。

## 阶段 8：代码结构收束

目标：降低国象代码与象棋代码并存的维护成本。

任务：

- 把 main.rs 的象棋分析后端抽到独立模块（可参考/改造未编译的 `engine/` 封装）。
- **清理或归档不参与编译的遗留 .rs**：`chess.rs`、`game.rs`、`pgn.rs`、`opening.rs`、`puzzle.rs`、`db/`、`engine/` 等——明确哪些删除、哪些作为参考保留并在文档标注。
- 统一 white/black → red/black 术语，消除 chess 残留命名。
- 隔离/移除前端死代码：`home/Databases.tsx`、死路由 `$databaseId.tsx`、`DatabaseLoader` 无效进度、`chessdb/api.ts`、`DetachedEval.tsx`。
- 棋谱库/开局库/残局训练稳定后，隔离或移除对应原版国象入口。
- 为象棋各模块补测试；在文档标明正式模块、实验模块、仅参考的上游模块。

验收：

- 新开发者能清楚区分正式象棋代码、实验代码、上游参考代码。
- `pnpm lint`、`pnpm test`、`pnpm build-vite` 稳定通过。

## 推荐顺序

1. **阶段 0 正确性与误导性入口清理**（先做，成本低、收益高）。
2. 阶段 1 引擎进程加固。
3. 阶段 2 棋谱库格式解析。
4. 阶段 3 象棋开局库。
5. 阶段 4 复盘报告增强。
6. 阶段 5 云库稳定化。
7. 阶段 6 残局训练正式版。
8. 阶段 7 界面专业化 / 阶段 8 结构收束（可与上述阶段穿插进行）。
